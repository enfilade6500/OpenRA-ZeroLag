## Install (per machine; the instances share the file)

    L=/opt/openra/current/usr/lib/openra
    sudo cp "$L/OpenRA.Game.dll" "$L/OpenRA.Game.dll.v1.2"     # once: keep v1.2 to roll back to
    sudo cp OpenRA.Game.dll "$L/OpenRA.Game.dll"
    sudo systemctl restart openra-ra@1234 openra-ra@1235 openra-ra@1236   # when nobody is playing; EU: also @1237

The first line the server logs after a game starts says which build is running:
`ZeroLag zerolag-v1.4-test10 on release-20250330: ...`.

## Settings worth setting

| Setting | Default | Note |
|---|---|---|
| `Server.MinGameSpeed` | `85` | With `Server.MinGameSpeedByPlayers` (`10:80,12:75,14:72`) the floor for the game's player count. With the floor fix a player it leaves behind is really left behind (see below). |
| `Server.ShowMapBriefing` | `False` | The lobby says `This map has a description; type !map to read it.` instead of printing it. `True` prints it as stock does. |
| `Server.LobbyOptions` | `explored=True,reusable-engineers=True,bounty=True` | `id=value` pairs, comma-separated, applied to every map that offers the option and does not lock it; `none` for the maps' own defaults. The admin can still change them for their game; they come back after every game and whenever the lobby empties. Players joining are told which options differ from the map's defaults (stock behaviour for admin changes). Other ids: fog, shortgame, crates, startingcash, startingunits, techlevel, gamespeed, factundeploy. |
| `Server.PaceLog` | `True` | Writes `Logs/zerolag-pace.log`, one line per player per second. About 1 MB per hour of play with six players. |
| `Server.ZeroLagNotice` | `True` | The join line `server: type !help for special server info and commands.` |
| `Server.AnnounceSpeedChanges` | `False` | `True` sends every "Slowing the game to N%" / "back to full speed" line to everyone, as v1.2 did. Default: only to players who typed `!speed on`. |
| `Server.NameSlowestPlayer` | as now (`False`) | Public lines say "the slowest computer"; `True` names the player. The private line is always sent. |
| `Server.MaxPlayerBuffer` | `0` | No automatic dropout buffer; players can still `!buffer 1.5` by hand. `1500` restores the v1.2 behaviour. |

## What to look for while playing

1. **On joining**: two lines, `server: type !help for special server info and commands.`
   and `Notice: the minimum game speed on this server for 14 players is 72%: ...` (for the
   map's slot count, or `for the next game is 77%, set by the admin`); the notice again, to
   everyone, when the map changes. `!minspeed` answers with the table and this map's figure;
   `!minspeed 77` as admin announces the change to the lobby. The server log notes the floor
   each game actually started with (`Minimum game speed for this game: 80% (10 players)`).
   `!help` answers with the bullet list (version, what the server does, the floor table,
   the commands); `!map` with the map's title and briefing, or "this map has no description".
   With `ShowMapBriefing=False` the lobby shows `This map has a description; type !map to
   read it.` instead of the briefing.
2. **Start**: the first frame comes 2 s after the last player loads (v1.3), so the first
   seconds should not stutter for the player who loaded last.
3. **A slowdown**: nobody sees a public line unless they typed `!speed on` (or the host set
   `AnnounceSpeedChanges=True`); `!speed` answers on demand. The slow player alone sees, once
   per game, 2.5 s after the slowdown: `NAME: the game is slowed to 84% because your computer
   is not keeping up (it is managing about 87%). Close other programs; on a laptop, plug in
   the charger and pick the performance power mode.` and, when the game is no longer slowed
   for them, `NAME: your computer is keeping up again.` Further slowdowns for the same
   player bring no further lines.
4. **The floor** (85% under 10 players, 80/75/72% from 10/12/14): a computer read a little under 85% gets the game at
   85% first (log: `...; the server does not go below 85%`) and is left behind only after
   falling six seconds behind there; one `can't keep up even at 85%` line per player per
   game ("The slowest computer can't keep up even at 85% speed..." — anonymous unless
   `NameSlowestPlayer`), no more marked/cleared/marked cycles; the game probes back to 100%
   within about ten seconds of leaving them. A player left behind gets no "keeping up
   again" line.
5. **Pace log**: `Logs/zerolag-pace.log` grows during a game; `queue_frames` (what the
   client reports) should track `backlog_frames` (what the server estimates) within a
   frame or two.

Messages that still go to everyone: a player left behind by the floor (once per player),
"X has stopped responding; the game continues without them", vote-kick lines, the join
notice. `!quiet` hides the first two (and the private lines) for the player who types it.
